# Premium Task 4: account read model и ограниченная история

Дата: 25.07.2026
Статус: `implemented_verified_local_delivery_unresolved`

## Цель

Ускорить owner-only `/settings/premium`, не ослабляя entitlement, privacy,
pagination или billing boundaries:

- один подготовленный account snapshot вместо независимых вызовов overview и
  payment history из Livewire;
- один entitlement read для одновременно полной активной сводки и последних
  `25` строк истории;
- сохранение полной `LengthAwarePaginator`, page name
  `premiumPaymentsPage` и URL-совместимости;
- `15` строк по умолчанию и жёсткий верхний предел `50`, даже при ошибочной
  runtime-конфигурации;
- явная проекция payment/plan/subscription/entitlement fields;
- стабильный порядок платежей `created_at DESC, id DESC`;
- отсутствие provider HTTP, shared user cache, migration и production DML.

## Проверенное исходное состояние

`AccountSettingsPage::render()` отдельно вызывает
`PremiumAccountQuery::overview()` и `payments()`. `overview()` выполняет
resolver read, второй entitlement read, отдельный latest subscription read и
ещё один active entitlement + plan read. `payments()` использует `SELECT *`,
а `max(5, config(...))` не имеет верхней границы.

Текущий Blade уже получает только safe arrays/paginator, не выполняет queries
и требует total/last-page navigation. Поэтому сохраняется `paginate()`, а
`simplePaginate()` и `cursorPaginate()` не подходят без изменения UI-contract.
Существующий индекс `premium_payments_user_time_idx
(user_id, created_at, id)` соответствует фильтру и порядку.

## Защищённые contracts

- `/settings/premium`, localized alias, auth/private/no-store/noindex
  middleware и self-context остаются прежними.
- `PremiumAccessSummary`, stable feature/source/status codes и server-owned
  entitlement остаются каноническими.
- `overview()` и `payments()` сохраняются как совместимые публичные методы;
  Livewire переходит на новый `snapshot()`.
- Blade variables `premiumOverview` и `premiumPayments` сохраняют назначение;
  одна строка payment history становится immutable
  `PremiumPaymentHistoryData` вместо shape-array.
- Paginator остаётся `LengthAwarePaginator` с `premiumPaymentsPage`.
- Сумма возврата читается из reconciled `refunded_amount_minor`; provider
  objects/IDs/private notes не выбираются и не передаются.
- Никакой Premium feature не меняет catalog/player/download/region/legal
  authorization.

## Риски и rollback

- Snapshot должен включать все активные entitlements, даже если они старше
  последних `25`; recent-history limit нельзя использовать как access limit.
- Subscription relation должна быть загружена для корректного explicit grace.
- Tie по времени обязан разрешаться `id DESC`, иначе страницы могут
  дублировать/пропускать строки.
- Runtime `history_per_page` ограничивается диапазоном `5..50`; default `15`
  сохраняется.
- Rollback code-only: вернуть два вызова Livewire и прежние query builders,
  удалить новый тест. Schema/data/cache/provider rollback не нужен.
