# Заметные карточки сериалов в персональных рекомендациях

Дата: 27.07.2026.

Статус: визуальное направление утверждено пользователем; спецификация
подготовлена для финальной проверки перед планированием реализации.

## Проблема

На `/discover/personalized` секция «Сериалы каталога» не имеет собственного
фона, а рекомендации выглядят как строки, разделённые тонкими линиями.
Действие «Подробнее» имеет прозрачный фон и становится визуально заметным
только при наведении. На desktop и mobile ссылка существует и сохраняет
минимальную высоту 44 px, но не воспринимается как основное действие для
перехода к сериалу.

## Утверждённое решение

Персональная секция получает спокойный светло-зелёный surface:

- фон `emerald-50`, тонкую рамку `emerald-200`, существующий
  `rounded-panel` и адаптивные внутренние отступы;
- белые карточки с постоянной рамкой, без градиента, изображения на фоне,
  glassmorphism и новой произвольной тени;
- одну колонку на phone и две колонки на широком desktop;
- белую вторичную кнопку обновления в заголовке секции;
- постоянную основную кнопку `Открыть сериал` на каждой карточке:
  `emerald-700`, белый текст, иконка направления, минимум 44 px по высоте,
  полная удобная ширина на phone и естественная ширина на больших экранах.

Белая карточка и её рамка принадлежат строке discovery, чтобы расположенная
под основной карточкой существующая персональная обратная связь оставалась
в том же визуальном контейнере. Название сериала продолжает работать как
растянутая canonical-ссылка, а отдельная кнопка располагается поверх неё
через существующую z-index boundary.

## Область изменения

Зелёный фон секции применяется только к персональному режиму
`/discover/personalized`. Общая recommendation-card получает заметное
основное действие во всех местах использования, чтобы один и тот же
компонент не менял affordance в зависимости от страницы. Другие discovery
режимы сохраняют существующий фон секции, сетку, порядок и пагинацию.

Сохраняются:

- H1/H2 hierarchy, число результатов и причины рекомендаций;
- rank, постер, metadata, описание и personal state;
- refresh, feedback, pagination и Livewire actions;
- route `titles.show`, route model binding и растянутая ссылка заголовка;
- одна колонка на phone, две на `xl`, отсутствие горизонтального overflow;
- текущие light-theme tokens и локальные FontAwesome assets.

## Переводы и доступность

Новый ключ кнопки добавляется одновременно в `lang/ru/catalog.php` и
`lang/en/catalog.php`: `Открыть сериал` / `Open series`. Stable identity,
route или cache key из переведённого текста не создаётся.

Кнопка остаётся обычной ссылкой, имеет видимый `focus-visible` ring,
контрастный текст во всех состояниях и touch target не меньше 44 px.
Существенное действие видно без hover. Полное название и причины не
становятся hover-only content. Existing poster alt и heading semantics
сохраняются.

## Архитектура и данные

Изменение ограничено Blade presentation, переводами, тестами и
документацией. Новые controllers, Livewire public state, JavaScript, CSS
rules, packages, routes, API fields, database queries, migrations, writes,
policies, permissions, cache keys и invalidation не добавляются.

Карточки продолжают получать только уже подготовленные и eager-loaded
данные. Blade не выполняет запросов и не содержит `@php`.

## Проверка

Реализация начинается с RED assertions:

- персональная секция имеет постоянный зелёный surface;
- строка результата имеет белый карточный surface;
- каждая recommendation-card содержит заметную основную ссылку
  `Открыть сериал`;
- title route и `data-title-card-details` сохраняются;
- другие discovery modes не получают персональный зелёный shell;
- RU/EN translation parity сохраняется.

После GREEN выполняются focused PHPUnit tests, Pint для изменённого PHP при
наличии таких изменений, Vite build и Playwright-проверка
`/discover/personalized` на desktop и phone. Browser acceptance проверяет
контраст, постоянную видимость действия, отсутствие horizontal overflow,
keyboard focus и неизменную работу перехода.

## Production impact и rollback

Изменение требует согласованной публикации Blade и собранных frontend
assets, но не требует migration, backup, worker restart, cache schema
conversion или data recovery. После deployment проверяются HTTP 200,
отрисовка новых classes, переход к `titles.show` и отсутствие stale view.

Rollback — согласованный revert Blade, translations, tests и документации с
повторной сборкой assets. Данные, cache payloads и пользовательское
состояние восстанавливать не требуется.
