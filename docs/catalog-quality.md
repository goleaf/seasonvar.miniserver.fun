# Центр качества каталога

Обновлено: 26.07.2026

Этот документ является единственным владельцем контракта оценки качества
карточек каталога. Административная интеграция описана в
[`administration.md`](administration.md), связи и индексы — в
[`DATA_RELATIONS.md`](DATA_RELATIONS.md), а importer и production operations
только ссылаются на этот контракт.

## Назначение и границы

Для каждого `CatalogTitle` хранится объяснимый `quality_score` от `0` до
`100` и набор текущих проблем. Оценка помогает редактору найти карточки,
требующие проверки, но не меняет автоматически публичную видимость, поиск,
рекомендации, SEO, теги, рейтинги, сезоны, серии или видеоисточники.

Центр качества является read-only административной очередью. Исправления
выполняются существующими административными и импортными boundaries с их
policy, audit, validation, transaction и cache invalidation. В центре нет
массовой автокоррекции, удаления тегов, запуска сетевых проверок или вывода
закрытых source/media URL.

## Модель оценки

Версионированный детерминированный evaluator начинает с `100`, вычитает
штрафы текущих проблем и ограничивает результат диапазоном `0..100`.
`scoring_version` позволяет безопасно пересчитать старые снимки после
изменения формулы.

Проверяются следующие группы сигналов:

- корректность и осмысленность названия;
- наличие года, страны, жанров, постера и содержательного описания;
- релевантность imported-тегов названию, оригинальному названию, описанию и
  жанрам с обязательным учётом current provenance;
- расхождения текущих редакционных полей с сохранёнными provider baseline;
- подозрительная форма оригинального названия или перевода;
- пропуски, дубликаты и противоречия regular-серий и счётчиков сезона;
- давность последней проверки source page;
- наличие опубликованного playable video и давность media health-check;
- некорректные или резко расходящиеся provider-рейтинги;
- аномальное количество или номер regular-сезонов.

Каждая проблема имеет stable code, category, severity, penalty и ограниченное
безопасное evidence. Evidence содержит только счётчики, названия полей,
ограниченные номера/названия и времена проверки. Raw provider payload,
source/media URL, HTML, credentials, private paths, персональные данные и
exception text хранить запрещено.

## Защита от ложных срабатываний

- Imported-тег не считается подозрительным, пока у него есть current
  provenance. Без provenance он становится кандидатом только при отсутствии
  нормализованного совпадения с title/original title/description/genres.
- Editorial/system assignments не признаются ошибочными только из-за
  отсутствия provider provenance.
- Большой номер серии сам по себе допустим. Gap рассчитывается внутри
  regular-сезона и становится проблемой только при существенном абсолютном и
  относительном разрыве.
- Provider baseline conflict означает необходимость редакционной проверки, а
  не автоматическое восстановление внешнего значения.
- Рейтинг проверяется по допустимому диапазону и межпровайдерному расхождению;
  высокая популярность или большое число голосов сами по себе не являются
  ошибкой.

## Хранение

`catalog_title_quality_snapshots` хранит один текущий снимок на
`catalog_title_id`: score, severity, количества проблем, флаг
`needs_refresh`, версию формулы, последнее source-время и `evaluated_at`.
Таблица индексирует score и очередь обновления.

`catalog_title_quality_issues` хранит текущие нормализованные проблемы.
Уникальность `(catalog_title_id, code)` обеспечивает идемпотентность;
`first_detected_at` сохраняется при повторной оценке, а решённые проблемы
удаляются. Индексы category/severity/title обслуживают семь административных
очередей без загрузки полного каталога в память.

Обе таблицы являются производными. FK использует cascade при фактическом
удалении `CatalogTitle`; откат кода может сохранить additive tables. Потеря
снимков не влияет на authoritative catalog data: их можно ограниченно
пересоздать командой.

## Пересчёт и актуальность

`catalog:quality-refresh` обрабатывает ограниченный batch без внешних
HTTP-запросов. Приоритет: отсутствующий снимок, `needs_refresh`, старая версия
формулы, затем просроченный снимок. Порядок детерминирован по приоритету и ID.

Scheduled запуск использует `withoutOverlapping()` и `onOneServer()`.
Начальный backfill выполняется постепенно этой же командой; migration не
сканирует весь каталог. Изменения конкретных title/relations/tags/episodes/
media помечают только известные ID как dirty после успешной transaction.
Глобальная invalidation без списка ID не запускает массовый `UPDATE`; её
покрывает возрастной проход scheduler.

Обычный и queued импорт помечают точный `catalog_title_id` после применения
подготовленной страницы. Даже корректный `304/not modified` помечает
существующий снимок, потому что меняется время проверки source page.
Media-health boundary делает то же после сохранения результата проверки.
Во время rolling window «код до migration» dirty tracker безопасно ничего не
записывает, а команда возвращает явный failure вместо SQL exception.

Расчёт загружает title facts и связанные агрегаты batch-запросами. Полные
графы episode/media не сериализуются, запросы не выполняются из Blade, а
пересчёт одного тайтла записывается короткой transaction.

## Административная очередь

Full-page Livewire-страница `/admin/catalog/quality` требует существующие
`administration.access` и `content.view` на route и component boundaries.
Отдельная permission identity не создаётся, потому что экран не изменяет
данные.

Доступны очереди:

- критические ошибки;
- подозрительные теги;
- конфликты данных;
- без постера;
- без видео;
- подозрительный список серий;
- давно не проверенные карточки.

«Без видео» означает только отсутствие опубликованного playable source.
Существующее видео, которое ещё не проверялось или давно не проходило
health-check, относится к очереди давности и не создаёт ложную карточку
«Без видео».

Очередь поддерживает bounded поиск, диапазон score, allowlisted сортировку,
page size `15|25|50`, детерминированную пагинацию и URL state. Пустые
значения не применяют фильтр, а `0` остаётся допустимой границей. Невозможный
диапазон и tampered values отклоняются серверной validation. Результат
показывает score, severity, краткие причины и ссылку на существующий
`/admin/catalog` через совместимый `catalog_q`; значения экранируются.

## Развёртывание, восстановление и проверка

До deploy нужен штатный backup assessment и `migrate:status`. Порядок:
additive migration, код, assets, restart реально используемых workers,
ограниченный ручной запуск `catalog:quality-refresh`, затем проверка schedule
и admin route. Недоступный scheduler означает stale queue, но не ломает
публичный каталог.

Если route cache был собран до deploy, после установки кода его нужно
пересобрать штатной deployment-командой; stale cache не содержит
`admin.quality`. Новый код допускает короткое окно до migration для public
read и existing import invalidation, но `catalog:quality-refresh` намеренно
возвращает failure, пока обе производные таблицы не установлены.

Rollback сначала возвращает прежний код. Производные таблицы рекомендуется
сохранить; их `down()` запускается только после остановки новой команды и
проверки отсутствия нового кода. Interrupted batch безопасно повторяется:
unique keys, transactions и сохранение `first_detected_at` делают пересчёт
идемпотентным.

Обязательные проверки: evaluator boundaries, schema/FK/indexes,
recalculation idempotency, command batch/order, route authorization,
queue/filter combinations, URL state, pagination, SQL query plan,
desktop/mobile accessibility, отсутствие source/media URL и публичная
регрессия каталога.
